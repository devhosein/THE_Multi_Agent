# Failures seen in real runs, and what the engine does about them

Three live runs on the user's Windows machine (Ollama, `ornith-1.5:9b` and `ornith-1.5:35b`) drove most of the
robustness work in `worker.py`, `llm.py`, `tools.py` and `orchestrator.py`. Every row below is a real failure.

| # | Run | What happened (from `.mission/events.jsonl`) | Root cause | Fix in the engine |
|---|---|---|---|---|
| 1 | test 1 (9B), task t4 | `HTTP 500: invalid tool call arguments for "write_file": unexpected end of JSON input` | The model's answer was **cut off mid tool call**: the context window was full (our own `num_ctx=16384`) while it was writing a large file | No `num_ctx` is sent by default (Ollama decides); history **compaction** (written content and old reads become short notes); on a cut-off, shrink harder and tell the model to write in parts (`write_file` + new `append_file`); `classify_llm_error` → `truncated` |
| 2 | test 1 (9B), t4 attempt 2 | ~9000 output tokens, no content, no tool call → "produced no work" | Same budget problem: thinking ate the room before any tool call | Same as above; `done_reason == "length"` is detected and treated like a cut-off |
| 3 | test 1 (9B), task t5 | `write_file backend/test.sh` 14 times, the agent itself writing "I'm in a loop" | Agents cannot run programs; the model kept trying to make a test runnable | Prompt rule "you cannot run programs or tests"; **loop detection** (same call ×3 → warning, ×5 → stop with a diagnosis); a write with identical content returns "no change, do not write it again" |
| 4 | test 2 (35B), task t1 | `HTTP 500: CUDA error: an illegal memory access was encountered` | A GPU/runner hiccup in Ollama | `transient` errors are retried with back-off (2 s, 5 s, 10 s) **without losing the attempt** |
| 5 | test 2 (35B), task t3 | Rule 1 again, on **both** attempts | The backend agent first read ~20 KB of frontend files: prompt ≈ 8k tokens + thinking + a large file > 16k | Same as 1; `read_file` is paged by model strength; a single enormous line is cut |
| 6 | test 3 (35B, no context limit) | Completed. Largest prompt: 14,666 tokens. One attempt hit the old 14-step cap | Confirms 1; the step cap was a second limit that got in the way | The step budget is now only a safety net (80–100 model calls); loops are caught separately |
| 8 | cafe-35b (35B, 2026-11-01) | All 4 tasks "verified", but the menu page stayed empty: the frontend (opened from another origin) called `http://localhost:8000/api/menu`, the backend sent no CORS header and did not serve the pages; `menu.js` also looked up elements its page did not have. The QA agent noticed, but it was the last task. A single agent on the same prompt scored 85/100 vs 53 (`eval/results/README.md`) | Each part was checked alone; nobody decided how the parts run together and nobody ran the whole | `integration.py` runs the project like a browser after every task and at the end (server start, pages, assets, API calls, CORS, element ids); problems in an agent's own files go back to it, problems between agents become a fix task right after the current one; contracts must have a `## Integration` section; `note_to_lead` reaches the lead at once and it answers, records a decision or changes the plan; the run fails honestly if problems remain |
| 7 | test 1, user message | "tell me what are u doing right now?" got a canned acknowledgement and was recorded as a **decision** | Messages were only queued | The addressed agent answers right away (next safe point) in its own voice; only instructions go into the decision ledger; questions just get an answer |
| 9 | cafe-35b-v4 (35B) | Three model calls hit the 600 s timeout; each retry of the SAME call took 2–22 s | Runaway generation (thinking that never ends), not slowness: the largest healthy answer in all runs was 28,957 tokens | `OllamaClient` caps the output (`num_predict` = 32,768, never `num_ctx`); a cut-off answer without a tool call is dropped and the agent is told to stop deliberating and act |
| 10 | cafe-35b-v4 | The backend agent built the pages itself inside `backend/frontend/`, then looped trying to make them fit | It saw only the other tasks' titles, not who builds which files and when | The worker prompt lists the team: each task's files and state ("starts after you"), plus the rule never to build another agent's files, not even a copy in its own folder. In v5 the backend agent said so and left the pages alone |
| 11 | cafe-35b-v5 and v6 (attempts) | "Use a warm color palette …" during approval got "I'll fold this into the frontend build" and **no decision**, so no agent would have seen it | The prompt asked whether the message "changes the work"; the lead read that as "changes the plan" | The question now defines an instruction as any requirement or preference, even one that fits the plan ("when in doubt, it is an instruction"); a restated instruction counts even if the flag says no (Ollama writes keys alphabetically, so the restatement comes first); the classification is logged |
| 12 | cafe-35b-v5 | Site scored 85 (= single agent). The reservation form was unstyled: the CSS styled `.form-group`, the HTML used `form-row` (same agent); a 404 for `/favicon.ico` cost the "no failed requests" points | Compaction replaced the written CSS with a note, so the agent no longer knew its own class names; nothing checked CSS against HTML | A compaction note keeps the names other files must match (classes a stylesheet styles, ids/classes a page or script uses); `integration.py` reports classes a page uses that its stylesheets never style (`style_missing`, with the unused CSS classes as a hint), a failing `/favicon.ico`, and finds pages served under other names (`/menu`) by following the pages' links |
| 14 | cafe-35b-v4 and v7 | v4: `server.py`, pages, CSS and JS overwritten 9 times with 75–90 byte files, then a loop; v7: "the appended text got written as literal text", four rewrites of a 1,200-line stylesheet | The files contained `<<11949 characters written to backend/server.py; read_file shows the file>>`: the note compaction leaves in the history. Models imitate their own history and wrote the note as content | `write_file` / `append_file` refuse content that contains such a note (`tools.PLACEHOLDER_RE`) and say what it is; nothing is written |
| 15 | cafe-35b-v6 | All 4 tasks verified, the stdlib check said "everything fits together", yet the menu page showed nothing and the reservation form threw `ReferenceError: form is not defined` | The server wrapped the menu twice (`{"menu": {"menu": …}}`); a variable used outside its function. Neither is visible without running the JavaScript; the QA agent only read the code | `browser.py` (optional, needs Playwright + a Chromium-family browser): loads every page the backend serves, reports JavaScript errors and failed requests, data fetched from the API that does not reach the page (with the real response), and fills in and submits the forms like a person; test bookings are undone. Without Playwright nothing changes (the app stays stdlib-only) |
| 16 | cafe-35b-v8 | The guard from row 14 refused every write of the note, but the agent kept trying (loop, two failed attempts) | The note was still inside the agent's own earlier calls, so it kept imitating them | Compaction now leaves only the path in an old write call; what was removed (size, classes, ids) is said in the tool result, which models do not imitate as their own output; a write without content gets an error that explains why earlier calls show none |
| 17 | cafe-35b-v8 | Every page's hero heading and the footer were white on cream (unreadable); all checks passed | `background: …, var(--coffee-800)` with only 900/700/500/300 defined: the browser drops the whole declaration | `integration.py` reports CSS variables used without fallback and defined nowhere (with the defined ones of the same family); `browser.py` reports text whose colour is (almost) the colour behind it (`low_contrast`). Both minor: sent back once |
| 13 | narrow window (side panel) | The approval panel covered the chat box although it invites a message; at 1000 px height the chat box was below the window | `position: fixed` over everything; `.main` had no `min-height: 0` in the stacked layout | The panel stops above the chat box (`--dock-h`, measured by `app.js`); `.main` may shrink; e2e checks it at 565×1000 |

When a task still fails after its attempts, the lead **diagnoses** it (`orchestrator.diagnose_failure`): retry with
concrete guidance, or split it into smaller tasks. If that does not work either, the user gets a decision panel with the
reasons and suggestions (retry, retry with a note, skip, stop). Infrastructure failures (Ollama down/crashing) are
diagnosed by rule, without asking the failing model.

How to investigate a new failure: open **Logs** in the UI (or the `log` events in `.mission/events.jsonl`), then
**Download report** — it contains the settings, every error with its evidence and the agent's last words.
